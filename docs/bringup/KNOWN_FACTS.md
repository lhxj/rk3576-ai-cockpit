# 已有实板证据摘要

来源：本会话用户粘贴的命令输出与人工确认。这里是脱敏摘要，未打包原始日志/图像/录音。
时间以实际测试记录为准，本文件整理于2026-10-01。

## 相机

CAM0曾以1632×1224 NV12运行300帧，v4l2-ctl显示约29.87~29.88fps。
单帧sizeimage=2996352（1632×1224×1.5）；用户确认转换JPG颜色与内容正常。
CAM1启用最初失败是`toverlay=`缺少d，修正后第二路probe成功。
随后CAM1流出现持续`MIPI_CSI2 ERR2:0x10000000`，单开CAM1亦复现。
已知正常Camera A + Cable A在CAM1短测成功，Camera B + Cable A也成功。
因此高度怀疑第二套连接组件，但尚无“每一段线缆永久损坏”的独立检测。

双摄枚举曾出现：
- `ov8858 3-0036`、`ov8858 4-0036`；
- `rkisp-vir0` / `rkisp-vir1`，mainpath曾为video22 / video31；
- 通用别名`video-camera0`曾指向video31，不能据此判断前后摄。

“probe可用”不等于“高速数据可用”，“两路分别短测”不等于“双路并发稳定”。

## 音频

`arecord -D hw:0,0 -f S16_LE -r 16000 -c 1 -d 5 ...`及`aplay`成功，用户听到录音。
后续Camera开启曾有ES8323 I²C写入-6，完整回归证据缺失，保留为风险。
ALSA卡名rockchip-es8388不单独证明Codec实物型号。

## 网络与显示

RTL8822CE PCIe枚举、rtw_8822ce绑定、固件加载、连接手机热点、SSH/SCP成功。
WSL连接超时曾由电脑与板子不在同热点造成，之后公钥SSH别名配置已确认完成。
不记录热点密码、固定IPv4、用户登录密码或SSH key。
用户随后确认HDMI显示正常，触控可用；USB输入设备WaveShare WS170120。
当前分辨率与X11/Wayland会话没有后续命令输出，仍需调查。

## shell与恢复经验

多行反斜杠后带空格曾导致timeout实际未运行。用户操作说明尽量给单行命令。
`dmesg -n 1`需要root权限且只改变console级别，不停止日志来源。
`timeout`发信号并不保证硬件停流；必须检查退出码、进程与stream off日志。
用sed -i编辑软链接可能替换链接本身：后续读实际路径，不能沿用历史假设。
MIPI插拔必须完全断电；正常poweroff日志/电源状态须确认，不能只看SSH断线。
