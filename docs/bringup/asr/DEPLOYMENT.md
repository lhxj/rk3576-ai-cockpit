# RK3576 file ASR deployment

This workflow uses only `/home/cat/cockpit/asr-target` on the board. It does not install system packages or alter boot, audio, camera, or service configuration. The existing `scripts/board/_common.sh` lock serializes board tasks. `rsync` is absent on the target, so the deployment script uses SCP. No root access is used.

1. In a separate local ignored `build/asr-deps` directory, acquire the official v1.11.3 `linux-aarch64-shared-cpu` release. Inspect archive members before extracting only `libsherpa-onnx-c-api.so` and `libonnxruntime.so`. Use the official v1.11.3 C API header from the Host release for native compilation. Do not put these in Git.
2. Invoke `scripts/board/deploy_asr_file.sh --dry-run` with absolute external `--model-dir`, `--wav`, `--sherpa-lib-dir`, and `--sherpa-header` paths. The script prints the precise source categories and asset paths. Then repeat with `--apply`. It transfers the selected main-project C++/CMake context, two AArch64 libraries, five selected model assets, and the same `0.wav`; the board recomputes every SHA256 before extracting the source context.
3. Run `scripts/board/build_asr_file.sh`. This uses target GCC 12.2 and CMake to build the main project's `cockpit_asr_file_test` and `sherpa_file_cancel_test`, runs `file`, `readelf -d`, `ldd`, and starts the executable with `--help`. A `libonnxruntime.so` or glibc/GLIBCXX resolution failure stops validation at this stage.
4. Run `scripts/board/test_asr_file.sh --load-only`. Only after this succeeds, run `scripts/board/test_asr_file.sh --full`. The second phase executes one recognition, three sequential recognitions in one process, real-engine session cancel, and expected failures for invalid model path, absent WAV, and 8 kHz WAV. Each test has a 120 s safety ceiling and 1 MiB per-case log limit; normal completion is a natural process exit. The script prints hashes, text, timing, sampled RSS/PSS, MemAvailable, CPU, and temperature, with a local ignored log under `build/asr-target-tests/`.

The model/WAV and runtime are external research assets. The package's executable examples are never deployed. Local `build/` and board `/home/cat/cockpit/asr-target` are the only generated locations. Distribution clearance for model and WAV remains unverified.
