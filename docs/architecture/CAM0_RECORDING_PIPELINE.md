# CAM0 recording pipeline

## Scope

The recording backend writes a raw H.264/AVC Annex-B elementary stream. The
original validated recorder was split during RTSP integration into a shared
encoder and a file sink; see `CAM0_RTSP_PIPELINE.md`. It does not mux MP4, use
CAM1, or claim zero-copy. `MediaService`
remains the sole CAM0 owner; Qt, Vehicle Core and the recorder never open a
second V4L2 device.

```text
OV8858 -> rkisp mainpath -> V4L2 MPLANE capture worker
  -> immutable owned CapturedFrame
       +-> capacity-one PreviewMailbox -> Qt preview worker
       +-> bounded encoder queue -> MppH264Encoder -> EncodedPacket
                                      +-> FileRecordingSink -> recording_<id>.h264
                                      +-> RtspServer
```

The capture callback deep-copies `bytesused` before QBUF. Preview may replace an
unconsumed frame. Recording uses a separate capacity-12 FIFO and never silently
drops. Its `submit()` is nonblocking so an overloaded encoder cannot stall DQBUF.
Queue full returns `RECORDING_BACKPRESSURE`, stops the current recording and
publishes canonical Recording `ERROR` through the adapter/Core runtime-result
path.

## Consumer ownership

`MediaService` tracks `preview_active`, `recording_accepting`,
`recording_active`, and the physical capture state independently.

- Preview first, then Recording: the recorder consumes frames from the existing
  capture; no second `open()` or `STREAMON` occurs.
- Recording first: the service prepares and starts CAM0 for the recorder without
  changing Preview to Streaming.
- Stop Recording with Preview active: drain and close the recorder, keep CAM0
  streaming for Preview.
- Stop the last consumer: STREAMOFF, unmap and close CAM0.

## Control lifecycle

The UI and synthetic ASR use the same control path:

```text
UI or Intent -> VehicleCommand -> VehicleCore -> RealMediaServiceAdapter
  -> MediaService -> IH264Encoder / FileRecordingSink
  -> RESULT -> canonical VehicleState -> UI
```

START emits ACK and sets `STARTING`. MediaService then prepares capture, opens
the output, initializes MPP, starts capture if necessary and waits for the first
encoded packet. Only that successful completion produces RESULT SUCCESS and
canonical `RECORDING`. ACK alone never reports success.

STOP emits ACK and sets `STOPPING`. MediaService first rejects new recording
submissions, the recorder consumes its queued owned frames, sends EOS on the last
queued frame when present, flushes and closes the file, and only then returns
RESULT SUCCESS and canonical `STOPPED`. If Preview has no remaining consumer,
capture is stopped after the recorder closes.

Repeated START while active and repeated STOP while stopped are idempotent and
do not create another encoder or file. Core deadline fencing prevents late
success from changing canonical state. Shutdown joins every worker; no detached
thread is used.

## H.264 baseline

| Setting | Value |
|---|---:|
| Input | NV12, 1632x1224, actual one-plane stride/bytesused |
| Output | Annex-B H.264 elementary stream |
| Rate control | CBR |
| Target/min/max bitrate | 8,000,000 / 7,500,000 / 8,500,000 bit/s |
| Input/output rate | 30/1 fps |
| GOP | 60 frames |
| Profile/level | High / 4.0 |
| Entropy coding | CABAC |
| Header mode | SPS/PPS on each IDR |
| Recording queue | 12 owned frames |

Input rows are copied into a 16-line-aligned MPP DRM buffer. This is a correct
copy baseline, not an end-to-end zero-copy claim. Output names are generated by
MediaService below its configured user-owned recording directory; ASR text is
never accepted as a path.

## Build boundary

`COCKPIT_ENABLE_MPP_RECORDING` is optional and defaults OFF. The V4L2 library and
Qt widgets do not link MPP. On RK3576 the option resolves `rockchip_mpp` through
pkg-config and adds `MppH264Encoder`; Host tests use `FakeH264Encoder` with the
real `FileRecordingSink`.

## Deferred work

MP4 mux, CAM1, RGA, DMA-BUF/DRM/EGL sharing and live VAD-to-intent are separate
gates. RTSP now consumes the same encoded Annex-B access units, but its separate
board evidence is required before `MEDIA_CAM0_RTSP_PASS`.
