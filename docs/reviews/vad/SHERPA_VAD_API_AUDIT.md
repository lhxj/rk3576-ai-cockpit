# Sherpa-ONNX v1.11.3 VAD API audit

Source observed: local reference `voice/sherpa-onnx/CMakeLists.txt` declares `SHERPA_ONNX_VERSION "1.11.3"`; `sherpa-onnx/c-api/c-api.h:774-915`, `c-api-examples/vad-sense-voice-c-api.c:73-150`, `sherpa-onnx/csrc/voice-activity-detector.cc:42-177`, and `sherpa-onnx/csrc/silero-vad-model.cc:94-145`. These are read only, at reference commit `be82e87cc334ae6e222f83f7555531d1ddebaa8b`.

`SherpaOnnxCreateVoiceActivityDetector` accepts a `SherpaOnnxVadModelConfig` and bounded buffer duration. Config specifies Silero ONNX path, probability threshold, minimum silence/speech seconds, window samples, maximum speech seconds, 16 kHz sample rate, thread count, and CPU provider. At 16 kHz, window 512 samples is the upstream example. `AcceptWaveform` accepts float PCM; `Detected` reports active speech after the model's minimum speech check; `Empty/Front/Pop` expose a completed `SpeechSegment` containing sample start/length; `Flush` finalizes an active segment; `Reset` clears detector state. There is no C API probability getter: event confidence must remain unavailable, not fabricated. The model itself implements trailing silence and minimum speech, so the pipeline must not add a second competing silence timer. The VAD internal circular buffer must be bounded.

The official v1.11.3 Linux x64 C API and the already deployed AArch64 C API export `CreateVoiceActivityDetector`, `AcceptWaveform`, `Detected`, `Empty`, `Front`, `Pop`, `Reset`, and `Flush` (local `nm -D`, source observed / target read-only observed). Thus the fixed runtime can be reused. VAD inference uses ONNX Runtime CPU; it does not use the RK3576 NPU. The existing board ONNX Runtime version is 1.17.1.

The official Sherpa VAD example uses threshold 0.5, minimum silence 0.5 s, minimum speech 0.5 s, and 512-sample windows. Our initial parameters are an engineering baseline and are **NOT PRODUCT-TUNED**.
