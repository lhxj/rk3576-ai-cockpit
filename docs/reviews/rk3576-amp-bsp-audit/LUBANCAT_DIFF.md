# LubanCat-3 v2 与候选 EVB 的差异

对照源为固定的 [LubanCat v2 DTS](https://github.com/LubanCat/kernel/blob/1dcb65a51c9a1f4adebe0896f522a04a265c248e/arch/arm64/boot/dts/rockchip/rk3576-lubancat-3-v2.dts)、其 [基板 DTS](https://github.com/LubanCat/kernel/blob/1dcb65a51c9a1f4adebe0896f522a04a265c248e/arch/arm64/boot/dts/rockchip/rk3576-lubancat-3.dts) 与 [EVB AMP DTS](https://github.com/LubanCat/kernel/blob/1dcb65a51c9a1f4adebe0896f522a04a265c248e/arch/arm64/boot/dts/rockchip/rk3576-evb1-v10-linux-amp.dts)。公开 DTS commit 并非本板当前运行 DTB 的 hash。EVB AMP DTS include `rk3576-amp.dtsi` 并额外预留 `0x41800000` 8 MiB；LubanCat v2 DTS 只 include 基板 DTS，未有 v2 AMP 预留或 mailbox 的实板证据。

| 资源 | 候选 RTOS/HAL | LubanCat/Linux 公开源码 | 差异 / 待证 |
|---|---|---|---|
| UART5/pinctrl | `R/bsp/rockchip/rk3576-mcu/board/evb/iomux.c` 选 `uart5_m0_iomux_config`，`board/common/iomux_base.c` 写 GPIO3_D4/D5（提交 `13735c5`）；console 115200 UART5。 | Rockchip `rk3576-amp.dtsi` 选 `uart5m2_xfer`，GPIO4_B0/B1。LubanCat v2 本身未定义 M0 console。 | 社区 m0 提交只证明一种 pinmux 候选；需核对 v2 40-pin 电路、串口被 Linux 占用状态、M0 UART clock/reset，不能同时让 Linux/RTOS 驱动同一 UART。 |
| MBOX/IRQ | HAL 有 MBOX0..13 register；RPMsg port 的 M0 client 表仅 0..3，非 MOS 示例用 ID3。 | AMP 示例 Linux `mailbox0` RX、`mailbox3` TX、link 0x03、IRQ route 指 CPU3。 | 示例是 CPU3 路径，不能直接移作 M0；M0 `0x04` 的 client/IRQ/controller 映射未实现和未在 LubanCat DTS 证明。 |
| firmware/shared DDR | M0 ELF `0..512 KiB` 别名，FIT load `0x47800000`；RPMsg 视图 `0x27d00000` 4 MiB，Linux 物理映射未证。 | EVB AMP DTS 另有 `0x41800000..0x41ffffff` 8 MiB；Rockchip AMP DTS `0x47800000` 为 rpmsg ring、`0x47a00000` DMA、`0x47c00000` shmem、`0x48000000` MCU。 | **FIT load 与参考 RPMsg ring 同址**，参考 MCU reserve 却在 `0x48000000`；直接套用会冲突。若 M0 共享区映到 `0x47d00000`，另会与 MCU reserve 重叠；该别名尚待证明。LubanCat v2 运行 DTB 和物理 RAM 布局仍需核实。 |
| clock/reset/power | `board/evb/board.c` 的 `clk_inits`/unused 表为空；`H/lib/bsp/RK3576/hal_bsp.c::BSP_Init` 为空；`RT_USING_PM=n`。 | Rockchip AMP DTS 把 MCU core/RTC、PCLK_MAILBOX0、UART5、timer10/11 等交给 AMP node。 | 需要确认 LubanCat bootloader/内核对 BUS M0、MBOX、UART5、timer 的初始化顺序、clock/reset/power domain；不能由 Host build 推断已开。 |
| I2C | `.config` 标记 I2C3/6/7/8，实际编译 `rtconfig.h` **只启用 I2C7**；EVB `iomux.c` 实际写 I2C7 m1，I2C8 m2 受未定义的 `RT_USING_I2C8` 排除。`board.c` 的 I2C8 400 kHz 表项仍保留但无活动 I2C8 设备。 | 基板 DTS I2C1、2 已开；v2 将 RTC 从 I2C2 转到 I2C3；基板 I2C3 还有 ES8388/ES8323 codec。历史 Camera0/1 sensor 在 I2C3/4。 | **I2C3 已属 Linux 的音频/RTC/相机相关链，禁止 M0 抢占。** 当前 I2C7 pinmux 也未与运行 DT/板图对齐；I2C6/8 如以后按 `.config` 再生成 header，会新增风险。MPU6050 不选具体脚位。 |
| PWM/GPIO/SPI | EVB `iomux.c` 直接配置 PWM0_CH0 m0 (GPIO0_C4)、SPI4 m3、SPI0 m0、GPIO1_D5 等；`.config` SPI0/4 和 PWM0 打开。 | LubanCat 基板 DTS `&pwm0_2ch_0` `status="okay"`，用于 `rockchip,remotectl-pwm-v4` IR key，另有多路电源/HP/系统状态 GPIO。 | **PWM0_CH0 有明确 Linux 冲突**；LED/按键/蜂鸣器目标仅软件模拟，应禁用无关 RTOS GPIO/PWM/SPI pinmux，不以 EVB 默认值写实际板。GPIO0_B6 在 Linux 是 LCD power，候选 `peri_s0_iomux_config` 也可操纵该 pin（本配置宏未开）；将来仍需查。 |
| camera/audio/显示/网络 | HAL 有 SoC API，不代表候选 BSP 取得这些外设所有权。 | LubanCat 基板 DTS 与 CSI include 配置 camera、codec、VOP、Type-C、Ethernet/PCIe。 | 保留 Linux 所有权；AMP 不应复用其 I2C/GPIO/clock/IRQ 或覆盖 DMA/CMA；需在运行 DTB 与真实板状态上核对。 |

`H/project/rk3576-mcu` 提供 Rockchip bare-metal 的 `gcc_bus_m0.ld`、`gcc_pmu_m0.ld` 等参考，不是该 RT-Thread BSP 的 active linker；本次没有拿其地址代替实际 `gcc_link.ld.S`。LubanCat 当前内核版本 `6.1.99-rk3576` 来自历史用户记录，公开固定 DTS/driver 与板端实际 build 的差异仍为未决项。
